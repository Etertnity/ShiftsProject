Веб-приложение дежурной смены: график смен, передача смены с кейсами, журнал, справочник команды и ICMP-монитор судов.

## 🚀 Возможности

- **График смен** — дневные и ночные смены (МСК), автозаполнение по циклу «день → ночь → отсыпной → выходной», замены, обмен сменами, разделение смены между сотрудниками, учёт отработанных смен и часов.
- **Передача смены** — открытые кейсы сами попадают в форму, статус меняется одним нажатием, «что сделано» — одна строка; всё пишется в историю кейса.
- **Кейсы (активы)** — категории, статусы и поля настраивает администратор; у каждого кейса полная история.
- **Excel** — выгрузка передач, кейсов и истории; загрузка журнала передач, который вели вручную.
- **Команда и профиль** — справочник коллег с контактами, которые сотрудник сам разрешил показывать; кнопки связи с дежурным.
- **ICMP-монитор** — графики потерь пакетов по судам из Zabbix.
- **Безопасность** — HTTPS, защита от подбора пароля, обязательная смена временных паролей, роли «сотрудник / администратор» (подробно — [SECURITY.md](SECURITY.md)).
- Тема день/ночь, анимации, адаптивная вёрстка для телефона и ПК.

## ⚙️ Настройки для администратора

Раздел **«Настройки»** (виден только администраторам) позволяет менять систему без разработчика:

- **Категории кейсов** — название, цвет, иконка, порядок, описание-подсказка. Категорию с кейсами нельзя удалить, но можно отключить: старые кейсы сохранятся, новые в неё создать нельзя.
- **Поля категории** — строка, текст, число, дата, выбор из списка, флажок, ссылка. Поля можно сделать обязательными и показывать в карточке. Переименование поля не ломает уже заполненные данные.
- **Статусы** — название, цвет, порядок, статус по умолчанию и признак «закрытый» (закрытые кейсы не попадают в передачу и скрыты в списке по умолчанию).

### Как устроена передача смены

1. В передачу автоматически входят **все открытые кейсы**. Они разложены по разделам — категориям из настроек; разделы свёрнуты, в заголовке видно, сколько кейсов, что уже отмечено и что закрывается.
2. Поиск по кейсам передачи (номер, судно, текст) сам раскрывает нужные разделы; переключатель «Изменённые» показывает только то, что вы отметили, — удобно проверить перед отправкой.
3. По каждому кейсу видна последняя запись истории; статус меняется одним нажатием, а «что сделано» — одна строка. Кейсы, обновлявшиеся в эту смену, стоят в разделе первыми.
4. **Закрытый кейс** записывается в эту передачу и в следующие уже не попадает. Если кейс закрыли не в передаче (например, на странице «Активы»), он один раз попадёт в ближайшую передачу — чтобы закрытие осталось в журнале смены.
5. Изменения применяются к кейсам вместе с передачей (одной транзакцией) и попадают в их **историю**.
6. Новый кейс можно создать прямо из формы передачи.
7. В журнале передач кейсы тоже сгруппированы по категориям: свёрнутый раздел показывает, сколько в нём записей и закрытых кейсов.
8. Формы передачи и нового кейса сохраняются как **черновик** в браузере — случайно закрытое окно не теряет текст. При выходе из системы черновики стираются.

Удалять передачи и кейсы может только администратор — сотрудник не может стереть историю работы.

### Поиск кейсов

На странице «Активы»: строка поиска (ищет в названии, описании, полях и **истории** кейса), статус, категории и кнопка **«Фильтры»**:

- **Обновлялся** — сегодня, за 7 или 30 дней, свой период или «без движения больше недели» (зависшие кейсы);
- **Кто работал** — кейсы, в истории которых есть записи выбранного сотрудника (или «Я»);
- **Сортировка** — недавно обновлённые, давно не обновлявшиеся, новые, старые, по названию.

## 📊 Обмен с Excel

На страницах **«Передачи смен»** и **«Активы»** — кнопка **Excel** (для всех сотрудников). Файл содержит три листа:

| Лист | Содержимое |
|---|---|
| **Передачи** | В том же виде, что и ручной журнал: `Дата` · `Фамилия сменного` · колонка на каждую категорию · `Разное` · `№ на сайте`. В ячейке категории — нумерованный список `N) Open/Continue/Close/Open-Close CASE#… <название> - что сделано` |
| **Кейсы** | Все кейсы: категория, название, описание, статус, даты, последняя запись, доп. поля |
| **История** | Каждое изменение кейсов за период: кто, когда, статус «было → стало», текст |

**Загрузка** (кнопка «Загрузить», только администратор) принимает журнал в этом же формате — и тот, что вели вручную, и выгруженный с сайта:

1. Выберите или перетащите `.xlsx` (до 5 МБ). Берётся лист «Передачи», иначе первый лист.
2. Сайт сам сопоставит колонки (Intraservice → CASE, Orange → Orange CASE, «Разное» → заметки, Change management → Change Management) — при необходимости поправьте в выпадающих списках.
3. В предпросмотре видно, сколько смен новых, сколько уже загружено и где ошибки. Ничего не сохраняется, пока вы не нажмёте «Загрузить».

Правила загрузки:

- Строка = передача смены. Время передачи — конец смены из колонки «Дата» (`17.10.2026 21:00 - 18.10.2026 09:00`).
- Кейс ищется по номеру `CASE#…` внутри категории, иначе по названию; не найден — создаётся.
- `Open` — кейс открыт, `Close` — закрыт, `Open-Close` — открыт и закрыт за смену, `Continue` — запись в историю, **только если текст изменился** (одинаковые строки из смены в смену не дублируются).
- Сотрудник ищется по фамилии; если его нет на сайте, фамилия сохраняется как автор записей.
- Повторная загрузка того же файла ничего не задваивает (смены узнаются по дате и фамилии или по колонке «№ на сайте»).

### График смен

На странице **«График смен»** есть переключатель **Календарь / Табель**. Табель выглядит так же, как Excel-файл графика сменных. Под ним кнопки **Excel** (для всех) и **Загрузить** (только администратор).

Формат — лист «Общее», каждый месяц отдельным блоком сверху вниз:

| Колонка D | E–BN | BO |
|---|---|---|
| год, месяц (название — в AI) | | |
| `число` | 1, 2, … (по две колонки на день) | `кол-во смен` |
| `день недели` | Пн … Вс | |
| `смена` | `д` / `н` | |
| `Имя Фамилия отработано` | часы в колонке нужной смены | `=SUM(E:BN)/12` |
| `Имя Фамилия станд.график` | часы по графику | `=SUM(E:BN)/12` |

Цвета в строке «отработано»: зелёный — отработано, жёлтый — замена или перенос, красный — не отработано. Ночная смена стоит в колонке «н» того дня, когда она началась.

Правила загрузки:

- Берётся лист «Общее» (или «График»), иначе первый лист. Месяц и год читаются из заголовка блока и проверяются по дням недели.
- У сотрудника берётся строка «отработано»; если её нет — строка без подписи или «станд.график». Строки без имени («1», «2») пропускаются.
- Имя ищется среди сотрудников сайта в любом порядке («Имя Фамилия» или «Фамилия Имя»). Кого нет на сайте — показываем списком, их смены не загружаются.
- 12 часов — полная смена. У двоих по 12 в одну смену — оба на смене одновременно. 4 + 4 + 4 — одна смена, отработанная по очереди. 8 часов у одного человека — короткая смена (09:00–17:00).
- Красная ячейка, 0 и текст («отп», «Нат») — смены нет.
- В предпросмотре по каждому месяцу видно, сколько смен новых, сколько изменится и сколько уже совпадает. Месяцы можно отметить. Режим «Как в файле» правит смены под файл, «Только новые» не трогает существующие. Смены, которых нет в файле, никогда не удаляются.
- «Станд.график» при выгрузке строится по тому, за кем числится смена на сайте. Отдельного «исходного плана» сайт не хранит, поэтому после замены через «Замена и подмена» план совпадает с фактом.

## 🌗 Тема и анимации

- **Тема день/ночь.** Переключатель в меню: «авто» (тёмная на ночную смену 21:00–09:00 МСК), «светлая», «тёмная»; по умолчанию — тёмная. Цвета заданы CSS-переменными в `frontend/tailwind.config.js` — для новых компонентов достаточно обычных классов Tailwind (`bg-surface` для фона карточек; оттенки `-700…-900` — только для текста). Акцентный цвет — золотой `accent`, фон меню — `navy`.
- **Баннер с морем** на главной и экране входа (`components/visual/OceanScene.tsx`) — WebGL-шейдер неба и моря: днём закат, ночью луна и звёзды (по времени смены, а не по теме). Поверх — SVG-силуэты: контейнеровоз с VSAT-антенной, кран, наземная станция и спутник. Ставится на паузу, когда не виден; без WebGL показывается обычный градиент.
- **Глобус** на странице монитора (`components/visual/FleetGlobe.tsx`) — библиотека [cobe](https://github.com/shuding/cobe) (MIT, ~19 КБ): порты, маршруты и орбита спутников. Крутится только когда виден; WebGL-контекст освобождается при уходе со страницы.
- **Анимации** — [Motion](https://motion.dev): переходы страниц, подсветка меню, модальные окна, появление и удаление карточек. При системной настройке «уменьшить движение» отключаются.
- Шрифты Inter и Oswald (заголовки, OFL) хранятся в проекте (`frontend/public/fonts`) — сайт не обращается к внешним сервисам и работает во внутренней сети.

## 👤 Профиль, команда, график, монитор

- **Профиль** (`/profile`) — каждый сотрудник сам меняет имя, должность, контакты и пароль, видит свои смены и часы за месяц и год. Логин видит только сам сотрудник. После смены пароля все остальные сессии этого сотрудника закрываются.
- **Команда** (`/team`, для всех) — справочник коллег: имя, должность и только те контакты, которые сотрудник открыл. В профиле у каждого контакта есть переключатель «Видно коллегам» (по умолчанию Telegram и почта видны, телефон скрыт). Скрытые контакты сервер вообще не отдаёт обычным сотрудникам, администраторы видят всё. На главной («Сейчас на смене», следующий дежурный) и в карточке смены — кнопки «Позвонить / Telegram / Почта».
- **Сотрудники** (`/users`, только админы) — контакты видны, логины и пароли скрыты. Админ может сбросить пароль: система покажет временный пароль один раз, при входе сотрудник обязан задать свой (до этого сервер не выполняет никаких других запросов). Сброс и отключение сотрудника сразу закрывают все его сессии.
- **Автозаполнение графика** — цикл «день → ночь → отсыпной → выходной»: сотрудник, вышедший в день 17-го, работает в ночь 18→19, 19-го после 09:00 и 20-го отдыхает. Нужно минимум 3 человека в очереди (с 4 и больше — без смен подряд). Режимы: «заполнить пустые» или «построить заново», перед сохранением — предпросмотр.
- **Факт отработки правит только администратор.** Смены, которые уже начались или прошли, сотрудник видит без права правки: нельзя заменить, разделить, удалить, перенести или добавить смену задним числом. Будущий график сотрудники меняют сами; автозаполнение у них пропускает начавшиеся смены. Проверка стоит на сервере, а не только в интерфейсе.
- **Рокировки** — в карточке смены вкладка «Замена и подмена»: заменить сотрудника, поменяться сменами или разделить смену на части (например, 09:00–15:00 и 15:00–21:00).
- **Статус смены** — прошедшая полная смена зелёная, разделённая между несколькими людьми — оранжевая, текущая подсвечена. Под календарём — сколько смен и часов отработал каждый за месяц.
- **ICMP-монитор** (`/monitor`) — графики потерь ICMP по судам из Zabbix: периоды 6/24/72 ч, фильтры, поиск (`/`), скрытие судов, добавление по Item ID или ссылке Zabbix. Браузер не знает пароль Zabbix — бэкенд сам ходит в API по настройкам `ZABBIX_*` из `.env` и кэширует ответы. Пороги — `MONITOR_WARN_THRESHOLD` / `MONITOR_CRIT_THRESHOLD`.

## 💻 Локальная разработка

Требования: Python 3.11+, Node.js 18+.

**Быстро — одним скриптом.** Он проверит версии Python и Node.js, создаст `backend/venv`, поставит пакеты Python и npm строго по зафиксированным версиям и создаст `.env` из `env.example`, если его нет. Повторный запуск безопасен — так же обновляются зависимости после `git pull`.

- Windows: двойной щелчок по `install_dependencies.bat` (или запуск из командной строки в папке проекта), затем `start_backend.bat` и `start_frontend.bat`.
- Linux / macOS: `bash scripts/install-dev.sh`.

**Вручную:**

```bash
cd backend
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements-dev.txt
python -m uvicorn main:app --reload
```

```bash
cd frontend
npm ci
npm start
```

Сайт — http://localhost:3000 (запросы `/api` CRA проксирует на :8000), документация API — http://localhost:8000/docs (в продакшене выключена).

**Первый вход.** При первом запуске на пустой базе создаётся администратор `Sideffect` (логин меняется переменной `DEFAULT_ADMIN_USERNAME`). Если `DEFAULT_ADMIN_PASSWORD` не задан, пароль генерируется случайно и **один раз печатается в консоли бэкенда**: `Создан администратор «…» с временным паролем: …`. При первом входе система попросит задать свой пароль.

Настройки — в файле `.env` в корне проекта (шаблон и описание всех переменных — [env.example](env.example)). `.env` в git не попадает.

## 📚 API

Все запросы, кроме входа, требуют заголовок `Authorization: Bearer <токен>`. Права: 👤 — любой сотрудник, 🛡 — администратор.

| Метод и путь | Права | Что делает |
|---|---|---|
| `POST /api/token`, `POST /api/login` | — | Вход (5 неудачных попыток → блокировка на 15 минут) |
| `GET /api/me`, `PUT /api/profile`, `POST /api/profile/password` | 👤 | Свой профиль и пароль (смена пароля возвращает новый токен) |
| `GET /api/users/public` | 👤 | Справочник «Команда» (только открытые контакты) |
| `GET/POST/PUT/DELETE /api/users/…`, `POST /api/users/{id}/reset-password` | 🛡 | Сотрудники, сброс пароля |
| `GET/POST/PUT /api/shifts/…`, `/generate`, `/swap`, `/{id}/assign`, `/{id}/split`, `/stats` | 👤 | График смен |
| `GET/POST/PUT /api/assets/…`, `/{id}/entries` | 👤 | Кейсы и их история. Фильтры списка: `asset_type`, `status`, `search`, `updated_from`, `updated_to`, `author_id`, `sort` |
| `DELETE /api/assets/{id}` | 🛡 | Удаление кейса |
| `GET/POST/PUT /api/handovers/…` | 👤 | Передачи смен. Список постранично: `?limit=20&offset=0` (до 200), всего — в заголовке `X-Total-Count` |
| `DELETE /api/handovers/{id}`, `DELETE /api/handovers/clear` | 🛡 | Удаление передач |
| `GET /api/exchange/export.xlsx?date_from=&date_to=` | 👤 | Выгрузка в Excel |
| `POST /api/exchange/import/preview`, `POST /api/exchange/import` | 🛡 | Загрузка журнала из Excel |
| `/api/settings/…` | 🛡 (чтение — 👤) | Категории, поля, статусы |
| `/api/monitoring/…` | 👤 (удаление судов — 🛡) | ICMP-монитор |

## 🐛 Устранение неполадок

| Проблема | Что делать |
|---|---|
| Не помню пароль администратора | Другой администратор сбрасывает его в «Сотрудниках». Если администратор один — см. [VPS_DEPLOYMENT.md](VPS_DEPLOYMENT.md#если-потерян-доступ-администратора) |
| «Слишком много неудачных попыток» | Подождите 15 минут (настраивается `LOGIN_LOCKOUT_MINUTES`) |
| После обновления «Не удалось загрузить страницу» | Обновите страницу — браузер подтянет новую версию сайта |
| Монитор пишет «Zabbix не подключён» | Заполните `ZABBIX_*` в `.env` и перезапустите бэкенд |
| Логи | `docker compose -f docker-compose.prod.yml logs -f backend` |
