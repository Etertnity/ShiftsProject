## ⚠️ Сделать владельцу в первую очередь

## Найдено и исправлено

Критичность: 🔴 критично (полный доступ без пароля / утечка всех данных) · 🟠 высокая · 🟡 средняя · ⚪ низкая.

### Аутентификация и сессии

| | Уязвимость | Было | Стало |
|---|---|---|---|
| 🔴 | **Подделка токена администратора** | Если `SECRET_KEY` не задан, использовался ключ `dev-secret-key-change-me`, записанный в публичном коде: любой мог выпустить себе токен администратора | Известного ключа больше нет: без `SECRET_KEY` генерируется случайный и сохраняется в `data/.secret_key`; `docker-compose.prod.yml` вообще не стартует без `SECRET_KEY`. Тест: токен на старом ключе отклоняется |
| 🔴 | **Пароль администратора по умолчанию `admin123`** | На новой установке любой мог войти как `Sideffect / admin123` раньше владельца | Без `DEFAULT_ADMIN_PASSWORD` генерируется случайный пароль и один раз печатается в лог; администратор создаётся, только если других администраторов нет |
| 🔴 | **Смена временного пароля проверялась только в интерфейсе** | С временным паролем (новый сотрудник, сброс, админ по умолчанию) можно было напрямую вызывать любое API, в т.ч. создать себе администратора | Сервер отвечает 403 на всё, кроме «кто я» и смены пароля, пока временный пароль не сменён |
| 🟠 | **Подбор пароля** | Ограничений не было | 5 неудачных попыток → блокировка на 15 минут по логину и по IP (сервер) + лимит 10 попыток/мин на IP в nginx; неудачные входы пишутся в лог |
| 🟠 | **Старые сессии жили после смены/сброса пароля и отключения** | Украденный токен действовал до 24 часов после смены пароля | В токене версия сессий: смена пароля, сброс, отключение сотрудника сразу закрывают все его сессии; текущая получает новый токен |
| 🟡 | Перебор логинов по времени ответа | Для несуществующего логина ответ приходил быстрее | Пароль проверяется всегда (одинаковое время), сообщения одинаковые |
| 🟡 | Слабые пароли | Минимум 6 символов | Минимум 8, максимум 128 (сервер и интерфейс) |
| 🟡 | Библиотека `python-jose` | Не поддерживается, известные CVE (CVE-2024-33663, CVE-2024-33664) | Заменена на PyJWT; алгоритм фиксирован (`alg=none` и подмена алгоритма отклоняются — есть тест) |

### Сервер, сеть, инфраструктура

| | Уязвимость | Было | Стало |
|---|---|---|---|
| 🔴 | **Нет HTTPS** | Пароли и токены шли открытым текстом | nginx: только HTTPS (TLS 1.2/1.3), HTTP → редирект, HSTS; Let's Encrypt с автопродлением (или самоподписанный по IP) |
| 🟠 | **Бэкенд открыт в обход nginx и файрвола** | Порт 8000 публиковался наружу; Docker открывает такие порты мимо ufw | Бэкенд и фронтенд доступны только внутри сети Docker; наружу — лишь 80/443 |
| 🟠 | Документация API открыта | `/docs`, `/openapi.json` показывали все эндпоинты | В продакшене выключены (бэкенд + nginx) |
| 🟠 | Скрипт развёртывания сбрасывал файрвол | `ufw --force reset` удалял все правила сервера | Правила только добавляются |
| 🟡 | Нет заголовков безопасности | Возможны clickjacking, MIME-sniffing, утечка Referer | CSP (`script-src 'self'`, без внешних ресурсов), `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: no-referrer`, `Permissions-Policy`, `Cache-Control: no-store` для API |
| 🟡 | Внешние запросы со страницы | Шрифт грузился с Google — каждый вход «светил» адрес и время | Шрифт хранится в проекте; встроенный скрипт вынесен в файл, чтобы CSP запрещал любые встроенные скрипты |
| 🟡 | Контейнер бэкенда работал от root | Взлом приложения = root в контейнере | Приложение работает от пользователя `app` (UID 1000), `no-new-privileges` |
| 🟡 | Подмена IP в заголовке | nginx передавал `X-Forwarded-For` от клиента | Передаётся только реальный адрес клиента |
| 🟡 | Сборка фронтенда без lock-файла | `package-lock.json` исключался из сборки — в образ могла попасть любая новая (или подменённая) версия пакета | `npm ci` строго по lock-файлу, без source map |
| 🟡 | CORS `*` по умолчанию | API разрешало запросы со страниц любых сайтов | По умолчанию CORS выключен (сайт и API на одном адресе) |
| 🟡 | Небезопасные советы в документации | `DATABASE_BACKUP.md` советовал выкладывать базу на transfer.sh и открывать папку бэкапов веб-сервером | Удалено; бэкап только по SSH/SCP, файлы `600`, папка `700` |
| ⚪ | Логи без ограничения размера | Логи Docker могли заполнить диск | Ротация: 10 МБ × 3–5 файлов |

### Загрузка файлов (импорт Excel)

| Угроза | Защита |
|---|---|
| XML-бомбы, XXE | Разбор через `defusedxml`, чтение в потоковом режиме |
| Zip-бомба | Проверка размера после распаковки (≤ 60 МБ) до разбора |
| Огромные файлы | ≤ 5 МБ (сервер читает не больше лимита), ≤ 10 МБ в nginx, ≤ 3000 строк |
| Формулы в выгрузке (formula injection) | Текст, начинающийся с `=`, сохраняется как строка — Excel его не выполнит (есть тест) |
| Кто может загружать | Только администратор; выгрузка — любой вошедший сотрудник |

## Что проверено и в порядке

- **SQL-инъекции** — все запросы через SQLAlchemy ORM с параметрами, «сырого» SQL с данными пользователя нет.
- **XSS** — React экранирует вывод, `dangerouslySetInnerHTML`/`eval` нигде не используются; внешние ссылки с `rel="noopener noreferrer"`.
- **SSRF через монитор** — история Zabbix запрашивается только по ID судов из базы; адрес Zabbix задаётся только в `.env`.
- **Пароли** — bcrypt; логины и пароли не отдаются ни в одном ответе API, кроме собственного логина в профиле.
- **Права** — каждый эндпоинт проверяет вход, административные — роль (покрыто тестами, в т.ч. попытки сотрудника вызвать админские операции напрямую).
- **Секреты в истории git** — кроме пароля администратора (см. выше) других секретов не найдено (ключи, токены, пароль Zabbix, базы данных).

## Остаточные риски и рекомендации

| Риск | Оценка | Рекомендация |
|---|---|---|
| Токен хранится в `localStorage` | Низкий при действующей CSP | Переход на httpOnly-cookie + CSRF-токен — при следующей крупной доработке |
| Сборка фронтенда на Create React App | Инструмент больше не развивается; ~100 уязвимостей `npm audit` относятся к инструментам сборки и dev-серверу, в браузер пользователей не попадают | Перевести сборку на Vite — отдельная задача |
| react-router 6: 2 «moderate» (open redirect через `\` в путях, SSR) | Не применимо: приложение переходит только по своим фиксированным путям и не использует SSR | Исправлено только в react-router 7 — обновить вместе с переходом на Vite |
| Счётчики попыток входа в памяти | Сбрасываются при перезапуске бэкенда | Достаточно для одного сервера; nginx-лимит действует независимо |
| График смен могут менять все сотрудники | Так задумано (сменщики сами меняются сменами) | Если нужно — ограничить удаление смен администратором |
| SQLite | Один файл на одном сервере | Обязательно копировать бэкапы на другую машину |

## Как проверять дальше

```bash
cd backend && python -m pytest tests/test_security.py -v     # проверки защиты
cd frontend && npm audit --omit=dev                           # уязвимости зависимостей
```

Внешний тест: после развёртывания проверьте сайт на https://observatory.mozilla.org и https://www.ssllabs.com/ssltest/ (ожидается A/A+), а `nmap -Pn <сервер>` должен показывать только 22, 80, 443.
